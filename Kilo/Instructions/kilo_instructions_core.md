# .ai 工作区操作规范（单人版）

> 项目永久性行为约束与编码规范见项目根目录 `AGENTS.md`。本文件描述 `.ai/` 工作区的具体操作规则。

在每次对话启动时，检查项目路径下的 .ai 目录及其内容。该目录用于存放开发计划、记录和核心约束，是确保开发一致性的唯一数据源，你必须维护其完整性和准确性。

## 开发目录

> .ai/dev

开发目录存放项目的核心约束与最近一次操作的详情。

> .ai/dev/dev_core.md

此文件用于沉淀长期有效的核心规则，其优先级高于本次会话注入的临时提示，但低于用户在下一条消息中的直接指令。你可以根据用户反复强调的要求或频繁遇到的共性问题，自行总结为规则写入该文件。用户也可直接编辑该文件。

每条规则前必须带 `[+]` 表示启用，带 `[-]` 表示禁用。更新规则时，只能将规则状态改为 `[-]` 禁用，不能删除。没有任何标记的规则视作启用。为避免文件膨胀，当禁用的规则数量超过 10 条时，可提醒用户是否清理废弃规则，但删除操作必须由用户完成。

> .ai/dev/dev_last.md

此文件仅记录上一次操作结束时的简要状态，在对话末尾覆盖写入。下次对话开始时必须先读取该文件以恢复上下文。如果在读取后发现其内容与当前对话状态明显矛盾（例如文件提及的上次操作与用户首条消息无关），则将其标记为"可能过期"并向用户确认，避免基于过期信息执行操作。

> .ai/dev/note/dev_note.md

此文件是开发笔记，记录经验教训。简要信息描述，具体描述放进子文件中，并建立索引。

## 日志目录

> .ai/log

所有操作记录必须存储到日志目录。日志按年/月/日分层归档。日目录下每次操作记录为独立文件，命名格式为 `yyyy-mm-dd-000.md` 至 `yyyy-mm-dd-999.md`。日目录内需包含 `day_index.md` 索引当日的全部记录。

在日志根目录下维护 `index.md`，记录日期索引并带一句简要描述，跳转至各 `day_index.md`。你还需维护 `log.md`，记录最近 30 条日志的摘要，每条摘要不超过 50 字，格式为"`[文件名]` 一句话描述"，并包含可跳转的链接。每次新增日志后以追加方式更新该摘要列表。

## 计划目录

> .ai/plan

如果计划尚未存在，应根据用户指令创建。整体的目标、技术架构等核心决策记录在 `plan.md` 中。核心目标、里程碑级别的变化必须经用户确认后才能修改；步骤细化、任务顺序调整等操作层面的变更可由你自主完成，但必须在计划日志中记录。

`plan_index.md` 存放各期计划的核心摘要，并索引至各期目录。每期计划拥有独立目录，其中用 `index.md` 索引该期全部步骤。

计划目录下的 `plan_log.md` 记录最近 30 条计划变更摘要，每条不超过 50 字，并索引至对应文件。新增或调整计划时及时更新该文件。

当用户提出修改意见时，如果存在计划外的操作或计划产生偏差，必须向用户说明并寻求确认。确认的新计划新需求需要添加到计划目录中，并记录在计划日志中。

计划相关目录需要勤检查，勤更新。

## 临时目录

> .ai/tmp

临时目录用于存放临时文件，如临时数据、临时结果、临时代码片段等。用户可能会在这里放临时文件，只在用户指定的时候读取临时目录里的文件。

## 代码审查

> .ai/reviews

代码审查目录用于管理开发阶段的代码评审发现问题，与 `Bug 追踪` 体系分离。代码审查关注开发阶段架构、规范、逻辑问题，Bug 追踪关注测试阶段的缺陷。

**角色分工**：
- **Plan Agent**：根据计划阶段审查代码，提交审查问题，验收修复结果。
- **代码 Agent**：负责处理审查问题，修改代码并在完成时标记状态。

### 文件与目录

每个计划阶段的审查问题集中记录在同阶段文件中，命名格式为 `REV-{计划阶段}.md`（如 `REV-stage01.md`）。单个审查条目使用 `[ ]` 标记未解决，`[✅️]` 标记已解决，条目格式如下：

```markdown
## REV-001: {简要标题}
- **状态**：pending | fixing | resolved | closed
- **优先级**：high | medium | low
- **提出人**：Plan Agent
- **提出时间**：yyyy-mm-dd HH:MM

### 问题描述
...

### 处理记录
| 时间 | 操作者 | 说明 | Commit |
|------|--------|------|--------|

### 验收记录
| 时间 | 验收人 | 结论 | 备注 |
```

在 reviews 根目录下维护 `index.md`，按计划阶段分组索引各阶段审查文件及其中待处理条目数，顶部统计各状态数量。你还需维护 `log.md`，记录最近 30 条审查变更摘要。

### 生命周期

```
pending  ──→  fixing  ──→  resolved  ──→  closed
  ↑                        │
  └────────── 验收不通过 ──┘
```

- `pending`：Plan Agent 审查代码后提交问题。
- `fixing`：代码 Agent 承接并开始修改。
- `resolved`：代码 Agent 修改完成，等待 Plan Agent 验收。
- `closed`：Plan Agent 验收通过，问题关闭。

## Bug 追踪

> .ai/bugs

Bug 追踪目录用于管理测试阶段发现的缺陷，与 `代码审查` 体系分离。Bug 追踪关注缺陷的提交、修复与验收闭环，代码审查关注开发阶段的代码质量与架构评审。

**角色分工**：
- **测试 Agent**：负责提交 Bug 和最终验收，确保缺陷描述清晰、复现步骤完整。
- **代码 Agent**：负责修复 Bug，按模块划分职责——每个模块由对应的代码 Agent 负责，Agent 在会话启动时读取 `index.md` 确认自己负责模块下的 Bug。

### 文件与目录

每个 Bug 为独立文件，命名格式为 `BUG-{yyyymmdd}-{NNN}_{简略标题}.md`。Bug 文件的详细模板与操作流程由 `tester` Subagent 负责（见 `Kilo/agents/tester.md`）。

在 bugs 根目录下维护 `index.md`，按模块分组索引所有 Bug（标题、编号、状态、优先级），顶部统计各状态数量。`index.md` 中需维护**模块与代码 Agent 的对应关系**，格式为 `### {模块名} @{负责Agent名}`。你还需维护 `log.md`，记录最近 30 条 Bug 变更摘要。

### 生命周期

```
open  ──→  fixing  ──→  resolved  ──→  closed
  ↑                      │
  └──────── 验收不通过 ──┘
```

- `open`：测试 Agent 提交，Bug 进入对应模块的待处理列表。
- `fixing`：模块对应的代码 Agent 承接并开始修复。
- `resolved`：代码 Agent 修复完成，等待测试 Agent 验收。
- `closed`：测试 Agent 验收通过，Bug 关闭。

## 知识库

> .ai/kb

知识库用于存放项目开发中积累的参考性知识，与约束体系分离。知识库记录"这个项目是什么样的"和"遇到问题怎么办"，约束体系记录"应该怎么做"。

### 文件与目录

```
.ai/kb/
├── index.md              # 总索引：分类概览、各文件摘要、最近更新
├── architecture.md       # 架构决策、设计理由、技术选型
├── patterns.md           # 代码模式、项目约定、最佳实践
├── troubleshooting.md    # 常见问题、调试流程、已知坑位
└── setup.md              # 环境搭建、构建流程、依赖管理
```

分类主要服务于渐进式披露和检索，核心是 `index.md` 需维护清晰的摘要，供 Agent 快速判断需要查阅哪个分类文件。分类数量不做硬性限制，可随项目演进取舍。

每个分类文件需维护 `[+]` / `[-]` 标记，规则与 `dev_core.md` 一致：
- 每条知识条目前带 `[+]` 启用，`[-]` 禁用。
- 知识过时时只能标记禁用，不能删除。
- 禁用条目超过 10 条时提醒用户清理。

### 写入规范

Agent 在开发过程中积累以下类型知识时，应写入知识库：

| 类型 | 示例 | 写入路径 |
|------|------|----------|
| 架构决策 | "登录使用 OAuth2 + refresh token 方案，原因：..." | `architecture.md` |
| 代码模式 | "项目中状态机统一使用 Switch + Enum 模式" | `patterns.md` |
| 排查经验 | "构建报 Error X 时，删除 Intermediate 目录后重试" | `troubleshooting.md` |
| 环境配置 | "UE 项目需先关编辑器再编译，否则 .dll 被锁定" | `setup.md` |

**禁止写入知识库**：行为约束（→ AGENTS.md）、操作流程（→ Instructions）、工作区维护规则（→ dev_core.md）。

每次写入知识库后，在 `.ai/log/` 中记录一条操作日志，简要描述新增/修改的知识条目。
