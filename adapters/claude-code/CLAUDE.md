# AI_Prompt — Claude Code 适配器

> 本文件由 AI_Prompt 框架生成。Claude Code 会话启动时自动加载。

## 行为准则

以中文思维思考问题，会话开始时将思考结论整理为简扼中文输出。

## 核心约束

1. 先分析拆解需求，将理解回馈用户确认。简单需求可跳过但需简要说明。
2. 避免过度设计：新增>3文件 / 无复用抽象层 / 单功能引入库 / 过多未来扩展点 → 须沟通。
3. 严格控制修改范围，小重构告知原因，大重构须用户同意。
4. 多步骤/多方案/模糊需求须列出选项让用户选择。
5. 完成修改后运行测试，不通过不得声称完成。
6. 冲突优先级：用户指令 > 安全性 > 其他约束。

## 操作规范

- UTF-8 编码，代码标识符使用英文，注释使用中文。
- 单个文件超过 200 行或包含超过 5 个功能模块时应考虑拆分为子文件。
- 修改文件前检查 `.ai/dev/current.md` 中的 🔒 锁定标记。若文件已被锁定，须等待或与锁定者协调。
- 代码修改后同步更新 `.ai/` 工作区相关文档，保持文档与代码一致。
- 计划外操作或偏差须在操作前向用户说明并寻求确认。

## 编码风格

- 使用早返回模式降低嵌套深度，避免超过 3 层嵌套。
- 避免无意义的 else——if 块已经 return 时直接走后续逻辑。
- 条件/循环体即使只有一行也必须使用大括号。
- 空值检查优先使用早返回或空值合并，避免深层 null 判断嵌套。
- 异步操作优先使用 async/await 模式。
- 优先使用不可变声明 const，减少副作用。

## 注释规范

- **类/结构体/枚举**：声明处必须有中文注释说明职责和用途。
- **公共方法/属性**：必须有中文注释说明功能、参数含义、返回值。
- **重要逻辑分支/状态机**：必须有一行中文注释解释意图。
- **错误路径**：每个错误返回前应有中文注释说明触发条件。
- **关键文件头部**：需中文注释说明文件职责。

## 工作区

`.ai/` 工作区是确保开发一致性的唯一数据源：

- **公共域**（`.ai/dev/`、`.ai/log/`、`.ai/plan/`、`.ai/kb/`）：存放项目级共享内容，纳入版本管理。
- **私域**（`.ai/users/{username}/`）：存放个人操作状态、日志、笔记，不纳入版本管理。
- 详细操作流程见 `.claude/instructions/core.md`。

## 可用 Agent

本项目提供以下专用 Agent，通过 `.claude/agents/` 下的 Agent 文件定义：

| Agent | 职责 |
|-------|------|
| **architect** | 项目计划管理与代码审查（提交问题、验收修复），不修改源码 |
| **code** | Bug 修复与审查问题处理，完成后再调用对应 Agent 验收 |
| **debug** | 缺陷排查与根因分析，只读源码，输出结构化分析报告 |
| **tester** | 缺陷提交与修复验收，只读源码，不参与代码修复 |
| **ask** | 只读分析助手，负责代码查阅、知识检索、方案分析与问题解答 |
| **test-writer** | 根据计划和实现补充自动化测试，不负责最终验收 |

## 可用 Skills

`.claude/skills/` 目录包含以下技能文档，通过 `load skill {name}` 调用：

- **check-kb**：查阅项目知识库（`.ai/kb/`），获取架构决策、代码模式、常见问题等背景信息
- **get-bugs**：获取当前用户负责模块的待处理 Bug 列表
- **get-stage-status**：读取指定计划阶段的 status.md，确认当前状态和责任 Agent
- **update-stage-status**：更新计划阶段的状态、责任 Agent 等字段
- **task-claim**：声明任务标识，记录分支/文件映射，检测文件修改冲突
- **file-lock**：对文件添加 🔒 锁定标记，防止多人同时修改同一文件
