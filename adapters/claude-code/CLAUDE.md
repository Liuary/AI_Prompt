## 行为准则

以中文思维思考问题，会话开始时将思考结论整理为简扼中文输出。

## 核心约束

1. 先分析拆解需求，将理解回馈用户确认。简单需求可跳过但需简要说明。
2. 避免过度设计：新增>3文件 / 无复用抽象层 / 单功能引入库 / 过多未来扩展点 → 须沟通。
3. 严格控制修改范围，小重构告知原因，大重构须用户同意。
4. 多步骤/多方案/模糊需求须列出选项让用户选择。
5. 完成修改后运行测试，不通过不得声称完成。
6. 冲突优先级：用户指令 > 安全性 > 其他约束。

## 操作规范

- UTF-8 编码，代码标识符英文，注释中文
- 文件>200行或>5功能模块时拆分
- 修改文件前检查 `.ai/dev/current.md` 中的 🔒 锁定
- 修改后同步更新 `.ai/` 工作区文档

## 编码风格

早返回（≤3层嵌套），避免无意义 else；条件/循环必须大括号；空值早返回；优先 async/await、const。

## 注释规范

类/方法必须有中文注释，重要分支/错误路径/文件头部需注释。
