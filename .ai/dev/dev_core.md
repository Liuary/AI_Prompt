# 项目核心规则

## [+] 研究文档规范 (2026-05-07)

- 研究/分析类文档放入 `docs/research/` 目录，按主题命名
- 文档内容以可验证的公开信息为基础，禁止编造数据或虚构引用
- 文档末尾标注撰写时间与核心参考来源

## [+] 知识库自动写入 (2026-05-13)

- 每次完成非平凡任务后，Agent 必须在 `dev_last.md` 的「经验暂存」中记录关键经验
- 下次会话启动时，Agent 必须检查是否有未归档经验，提醒用户确认后归入 `kb/`
- 归档经验写入对应分类文件（`architecture.md` / `patterns.md` / `troubleshooting.md` / `setup.md`），格式：`## [+] {标题} ({日期})`
- 归档后更新 `kb/index.md`「最近更新」表格，并在公共日志 `.ai/log/` 中记录

## [+] 跨会话记忆 (2026-05-13)

- 每次会话结束时，Agent 必须覆盖写入 `dev_last.md`，使用标准模板（含待续事项、关键决策、经验暂存）
- 下次会话启动时，Agent 必须先读取 `dev_last.md` 恢复上下文
- 若 dev_last.md 内容与当前对话矛盾，标记"可能过期"并向用户确认后再操作

## [+] 文件拆分原则 (2026-05-13)

- 单文件超过 200 行或包含多个可独立描述的功能模块时，必须拆分为子文件并建立索引
- 部署和文档类文件按工具/模块拆分（如 `deploy/{tool}.py`），父文件仅保留入口和跳转链接
- 拆分后父文件行数应控制在 50 行以内，子文件各司其职
- 新增工具时在对应目录下新增子文件，同步更新索引文件（README.md）

## [+] 知识库 Wikilink 写入规则 (2026-06-04)

- Agent 归档经验写入知识库条目时，必须使用 `[[条目名]]` 格式建立条目间的关联引用（格式规范见 `specs/KB_LINK_SPEC.md`）
- 写入新条目或更新条目内容时，扫描 `kb/index.md` 中的注册表获取已有条目标题列表，自动匹配关键词，在正文中建议添加 `[[链接]]` 引用
- 鼓励在知识条目正文中使用 `[[wikilink]]` 引用相关条目，建立可遍历的双向链接网络。引用目标必须是 `kb/index.md` 中已注册的条目名，不支持链接到不存在的条目
- 写入后同步更新 `.ai/tmp/graph.json` 图谱缓存（运行 `python scripts/build_kb_index.py --graph`）
- 链接图是索引缓存，Markdown 文件是 single source of truth；链接可从 Markdown 文件中解析重建
