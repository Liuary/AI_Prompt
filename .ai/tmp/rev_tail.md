

## REV-008: Architect 审查完成后未及时归档审查结论（需修改提示词）
- **状态**：pending
- **优先级**：high
- **提出人**：Architect Agent（自检）
- **提出时间**：2026-05-13 01:28

### 问题描述
Architect Agent 在完成 v2.0 进度审查后，未按规范立即创建 REV-stage-01.md 并将审查结论写入，而是仅通过对话文本输出。事后经用户多次提醒才补建审查文件。

**根因**：Architect Agent 当前的提示词（Kilo/agents/architect.md）中，代码审查章节仅描述了「审查问题提交」的流程，**未明确要求审查完成后立即归档到 REV 文件**。Agent 遵循提示词执行，缺少这一步会导致审查结论仅存在于对话上下文中，其他 Agent 无法获取。

**修复目标**：修改 Kilo/agents/architect.md 提示词，在代码审查章节末尾增加强制归档步骤——审查完成后必须立即创建/更新对应阶段的 REV-{stage}.md 文件，写入所有审查条目后再向用户输出摘要。

**注意**：之前的「自查自改」操作（Architect 自行补建文件并标记 closed）违反 REV-009 原则，无效，需由 code agent 执行以下操作：
1. 修改 Kilo/agents/architect.md，在审查流程末尾增加归档步骤
2. 验收确认提示词修改正确后，再由 Architect（新会话）验证

## REV-009: 审查/Bug 发现者不得自查自改，必须交由其他 Agent 处理
- **状态**：pending
- **优先级**：high
- **提出人**：Architect Agent（自检）
- **提出时间**：2026-05-13 01:28

### 问题描述
REV-001~004 由 Architect 自行发现并自行修复，REV-008 最初也被 Architect 自行标记为 closed。这违反了代码审查流程的设计原则——发现者与修复者应分离，否则缺乏独立验收环节，问题可能被草率关闭。

当前约束体系（AGENTS.md / Instructions / dev_core.md）中**未明确禁止自查自改**。Agent 在权限允许时（如 Architect 可编辑 .ai/ 目录）会自行修复审查发现的问题，导致审查流程形同虚设。

**修复目标**：在 AGENTS.md 或 Kilo/agents/architect.md 中增加明确约束：
- Architect 提交的审查问题，不得由 Architect 自行修复，必须交由 code agent 处理
- 测试 Agent 提交的 Bug，不得由测试 Agent 自行修复，必须交由 code agent 处理
- 即使提交者拥有目标文件的编辑权限，也禁止自查自改
- 例外：工作区基础结构自检（如补建缺失目录/空文件）可由任意 Agent 执行，不视为自查自改
